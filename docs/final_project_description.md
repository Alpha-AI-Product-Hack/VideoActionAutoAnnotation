# Итоговое описание проекта: Автоматическая разметка действий по видео

## 1. Общее описание
Данный проект представляет собой комплексное программное решение (веб-приложение) для автоматизации процесса разметки действий людей на коротких видеороликах. Система обеспечивает полный цикл обработки: от загрузки исходного видеофайла до выгрузки готовой разметки в форматах JSON и CSV. Ключевой особенностью решения является гибридный подход, сочетающий передовые модели машинного обучения (Computer Vision, Foundation Models) для автоматического извлечения интервалов и семантики, а также удобный пользовательский интерфейс для концепции **Human-in-the-loop (HITL)** — ручной валидации и корректировки результатов.

## 2. Проблематика
Разметка видеоданных (особенно от первого лица, egocentric video, или сложных сборочных процессов) — это чрезвычайно трудоемкий, медленный и дорогостоящий процесс. Разметчикам приходится покадрово просматривать видео, вручную определять границы начала и конца действий, а также классифицировать само действие и объект, с которым происходит взаимодействие. 
Основные проблемы текущих ручных подходов:
*   **Низкая скорость**: Разметка одной минуты видео может занимать до 15–30 минут рабочего времени.
*   **Человеческий фактор**: Усталость разметчиков приводит к неточностям в определении границ (таймстемпов) и пропуску мелких действий.
*   **Отсутствие гибкости**: При изменении словаря действий (taxonomy) часто требуется переразметка всего датасета.

## 3. Постановка задачи
В рамках хакатона была поставлена задача разработать автоматизированную систему, которая должна:
1.  Принимать на вход короткое видео и набор правил (словарь действий и объектов).
2.  Автоматически сегментировать видео на отдельные осмысленные действия.
3.  Определять точные временные границы (start, end) для каждого сегмента.
4.  Классифицировать тип действия (Action) и связанный с ним объект (Object).
5.  Выбирать репрезентативный ключевой кадр (Keyframe) для каждого действия.
6.  Предоставлять пользователю таймлайн и визуальный редактор для просмотра и исправления сгенерированной разметки.
7.  Экспортировать итоговый результат в JSON или CSV.

## 4. Описание технического решения

Архитектура системы разделена на три слабосвязанных слоя, что обеспечивает масштабируемость и простоту интеграции:
*   **Frontend (UI)**: React SPA + TailwindCSS. Отвечает за загрузку, рендеринг видео, отрисовку интерактивного таймлайна и интерфейса редактирования.
*   **Backend (API)**: FastAPI (Python). Обеспечивает маршрутизацию, валидацию правил (rules.json), управление задачами и передачу данных в ML-модуль.
*   **ML Pipeline**: Ядро системы, выполняющее анализ видео.

### Техническое устройство ML Pipeline
Пайплайн логически разделен на два последовательных этапа: **поиск границ (нарезка)** и **семантическая классификация**.

#### Этап 1: Поиск границ действий (Boundary Proposals)
Для определения начала и конца действий без жесткой привязки к конкретным классам (open-vocabulary) используется ансамбль из трех сигналов:
*   **Motion (Оптический поток)**: Анализирует глобальные движения и остаточные локальные движения (движения рук/объектов), находя пики изменений и паузы.
*   **SAM3 (События контактов)**: Отслеживает взаимодействие рук и объектов. Границы определяются по моментам смены состояния: "взял предмет", "отпустил предмет", "сменил предмет".
*   **ABD (V-JEPA + DDM-Net)**: Использует базовую модель V-JEPA для извлечения видео-эмбеддингов. Границы определяются по "провалам" косинусного сходства между соседними окнами (резкая смена семантики сцены).
Сигналы нормализуются и объединяются с помощью взвешенного алгоритма NMS (Non-Maximum Suppression) в единый список кандидатов-интервалов.

#### Этап 2: Классификация действий и объектов (Action & Object Classification)
После того как видео нарезано на временные сегменты, для каждого сегмента определяется его смысловое наполнение с использованием парадигмы Open-Vocabulary (без дообучения на фиксированных классах):
*   **Классификация Action (X-CLIP)**: Для определения действия используется модель X-CLIP. Алгоритм вычисляет видео-эмбеддинг для вырезанного сегмента и текстовые эмбеддинги для всех названий действий, переданных пользователем в `rules.json`. Классификация происходит путем вычисления **косинусного расстояния** между эмбеддингом видеосегмента и текстовыми эмбеддингами действий. Выбирается класс с наибольшим сходством.
*   **Классификация Object (SAM3 / CLIP-based)**: Аналогичным образом определяется объект взаимодействия. Используя маски и эмбеддинги из SAM3 (Segment Anything Model 3) в сочетании с текстовыми промптами объектов, система сопоставляет визуальные признаки удерживаемого предмета с текстовыми названиями объектов через косинусное расстояние.

## 5. Достигнутые результаты
На текущий момент (в ветке `test_merged_pipeline`) команда реализовала полностью функционирующий прототип:
1.  **Frontend & Backend**: Полностью реализован и отлажен Web-интерфейс. Пользователь может загружать видео, задавать правила в формате JSON, просматривать сгенерированный таймлайн и редактировать разметку (изменять границы, классы). Реализована выгрузка в JSON/CSV. Связка UI ↔ API работает стабильно (с использованием mock-пайплайна для отладки контрактов данных).
2.  **ML Pipeline**: Реализованы и протестированы изолированные модули:
    *   Скрипты извлечения сигналов (Motion, SAM3, ABD).
    *   Логика фьюжена (слияния) границ.
    *   Реализованы механизмы X-CLIP ранжирования для действий.
3.  **End-to-End**: Сформирована четкая архитектура, где замена заглушки (mock) на вызов реального Python-модуля Pipeline требует минимальных изменений в Backend-коде, так как контракты данных (Pydantic-схемы) уже строго согласованы.

## 6. Планы дальнейшего развития
*   **Полная интеграция ML в API**: Бесшовная стыковка тяжелого ML-пайплайна с FastAPI через асинхронные очереди (например, Celery/Redis), чтобы интерфейс не блокировался при обработке длинных видео.
*   **Оптимизация инференса**: Квантизация моделей X-CLIP и SAM3, а также кэширование эмбеддингов для достижения обработки видео быстрее, чем в реальном времени (Real-time x2).
*   **Продвинутая аналитика (LLM)**: Внедрение легковесной мультимодальной LLM для анализа сложных логических цепочек (например, проверка правильности порядка сборки деталей).
*   **Многопользовательский режим**: Добавление ролевой модели (Admin, Annotator, Reviewer) для внедрения системы в корпоративные процессы разметки данных.

## Краткая аннотация

Готовим SPA, которое по короткому ролику человека (MP4/MOV, 5–30 с, одна основная операция) строит **черновик разметки**: временные шаги, действие, объект, ключевой кадр. Человек проверяет, правит и выгружает JSON/CSV. Ценность для жюри: качество автоматических лейблов, не полировка редактора.

Границы шагов предлагает ансамбль (SAM3, кинематика пальцев, концепты по эмбеддингам, motion flow). На уже вырезанный шаг действует open-set классификация действия. Интерфейс: макет в Figma и React SPA в работе.

Проверка качества идёт на публичных датасетах, которые дал кейсодатель ([Assembly101](https://assembly-101.github.io/), [EPIC-KITCHENS](https://epic-kitchens.github.io/)): на них разметка уже есть, отдельных  с ручной GT не собираем. Чисел Step-level F1 / 80% семантики на held-out пока нет: гипотезы качества **в тесте**, не подтверждены.

---

## Проблематика

Ручная разметка короткого действия: посмотреть ролик, нарезать шаги, подписать verb–object. По брифу кейса это 15–30 минут на ролик 5–30 с; 1000 роликов оцениваются в 0,5–2 млн ₽. Целевое ускорение: не менее 3×, автопрогон не дольше 2 минут. 

По Q&A кейсодателя основное время и штраф за ошибку приходятся на «что произошло» (действие/объект), а не на миллиметровку границ. Пользователь кейса: инженер / робототехник; каждое видео всё равно смотрит человек

---

## Актуальная постановка задачи

**Вход:** одно видео, один человек, одно главное действие, без склеек, ≥ 720p.

**Выход:** список шагов по контракту (`docs/Data_Sample.md`), затем правка в UI и экспорт JSON/CSV. Для сдачи жюри достаточно финального файла.

Поля шага:


| Поле                          | Смысл                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| `start_ms`, `end_ms`          | границы шага                                                                          |
| `action`, `object`            | open-vocabulary; объект из видео, не из заранее данного класса; объекта может не быть |
| `keyframe_ms`                 | кадр внутри шага (стилистика; по умолчанию середина)                                  |
| `confidence`, `model_version` | служебные                                                                             |


Шаг: осмысленный verb–object, не микродвижение. Пересечения двух рук допустимы. `unknown` и паузы без действия допустимы. F1 жюри считает по `action` (one-to-one, temporal IoU ≥ 0,5 **и** верный класс); объект отдельно; синонимы не режут строкой.

**Целевые метрики кейса**

1. Step-level F1 ≥ 0,75; средняя ошибка границ ≤ 2 с на IoU-совпадениях.
2. На шагах с tIoU ≥ 0,5: ≥ 80% верных `action` и `object`.
3. Обработка ≤ 2 мин; валидный JSON/CSV на 100%.

**Вне скоупа:** ROS / управление роботом / 3D / усилия; обучение большой модели с нуля; интеграция Label Studio / CVAT; биллинг; доверие к разметке без просмотра.

## Выбранное техническое решение

Пайплайн делится на два ML-контура и тонкий UI.

```
видео
  → decode
  → ансамбль proposals границ
       (1) SAM3: рука + объект в руке, трек, разъединение → отрезок
       (2) пальцы по маске руки, кинетика между кадрами → уточнение границ
       (3) концепты по эмбеддингам V-JEPA 2.1 и второй предобученной сети
       (4) motion flow после вырезания масок кистей (алгоритмически, пока слабое звено)
  → open-set классификация action (и отдельно object) на вырезанном шаге
  → keyframe = кадр внутри сегмента
  → schema validate
  → UI: просмотр / правка одной ошибки
  → JSON/CSV
```

Классификация шага: frozen video–text модель одного семейства (сейчас X-CLIP), словарь текста кешируется, клип режется по меткам (для честной оценки) или по proposal пайплайна (в проде). Top-k кандидатов и `unknown` при низкой уверенности. Тяжёлый VLM не на каждый шаг, чтобы уложиться в 2 минуты.

Оценка: held-out GT Assembly101 / EPIC-KITCHENS, не самописный мини-набор. Родная гранулярность этих датасетов часто мельче «осмысленного шага»; правило matching к GT нужно зафиксировать до публикации цифр (мержить GT или скорить as-is).

## Предварительные результаты

Количественных Step-level F1, ошибки границ и 80% семантики на held-out **пока нет**. Ниже качественная картина по каналам нарезки (оценка автора сегментации):


| Канал proposals                                 | Наблюдение                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------ |
| SAM3: рука + объект, разъединение треков        | рабочий источник границ                                            |
| Кинетика пальцев                                | уточняет отрезок                                                   |
| Концепты V-JEPA 2.1 + вторая предобученная сеть | на практике даёт полезные границы, несмотря на «мягкую» постановку |
| Motion flow без кистей                          | считается алгоритмически, **самый слабый** канал                   |


Классификатор: инфраструктура ranking и stub-прогоны есть; X-CLIP подключён. Публичной таблицы Top-k на 10 val-роликах Assembly101 / EPIC в этом репозитории ещё нет.

UI: трёхколоночный макет (загрузка и правила / превью и таймлайн / список действий) воспроизводится в React на фиктивных шагах.

Q&A с кейсодателем **подтвердила правила кейса** (инженер как пользователь, open-vocabulary, оценка за модель, финальный JSON, публичные датасеты). Она **не** подтвердила, что инженер примет JSON как старт обучения, и не заменила цифру F1.

## Ограничения

- Нет эталонных роликов от заказчика; скрытый тест (8–12 клипов) может отличаться доменом и ракурсом от Assembly101 / EPIC.
- Организаторы не дают GPU; на финале запуск у них ещё не зафиксирован. Внешние API допустимы, но каждый сегмент нельзя кормить долгим VLM.
- Ансамбль сегментации тяжёлый (SAM3, трекинг, несколько сетей): риск не уложиться в 2 минуты без прореживания FPS и отключения слабых каналов.
- Гранулярность GT датасетов ≠ «осмысленный шаг» кейса: без правила matching легко завалить F1 из-за микрошагов.
- Классификатор пока скорится на границах из датасета. В проде границы придут от ансамбля: ошибка нарезки ударит по action accuracy.

## Открытые вопросы

1. Итоговое правило слияния четырёх proposal-каналов (веса, NMS, запрет микродвижений).
2. Held-out сплит и формула matching к GT (мержить лейблы или нет).
3. Словарь vs полностью открытый текст на скрытом тесте (команда может задать словарь на серию, организаторы список не дают).

## План работ до финальной версии

Порядок: **нарезка → семантика → скорость/экспорт → тонкий UI**. Без F1 границ семантика и интерфейс не спасают оценку.

1. Склеить ансамбль proposals в один сегментатор, отключить или ослабить motion flow, если он шумит.
2. Зафиксировать сплит Assembly101 / EPIC и правило гранулярности; снять Step-level F1 и ошибку границ. Цель: F1 ≥ 0,75, границы ≤ 2 с. Если F1 < 0,50: укрупнять шаги.
3. Прогнать open-set классификацию на тех же сегментах (сначала на GT-cut как верхняя оценка, затем на proposal). Цель: ≥ 80% action/object на IoU-совпадениях.
4. Сквозной прогон: ≤ 2 мин, валидный JSON/CSV по контракту.
5. Подключить React к реальному JSON (без полировки UX).

Не делаем до финала: CVAT/Label Studio, audit trail, обучение большой модели, идеальный keyframe, «доверие без просмотра».

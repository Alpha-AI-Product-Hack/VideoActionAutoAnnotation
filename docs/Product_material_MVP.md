# 1. Продуктовая записка

Автоматическая разметка действий по видео · AI Product Hack 2026

## Решение, которое фиксируем

Продукт готовит **черновик разметки короткого видео** (шаги, границы, действие, объект, ключевой кадр) в JSON/CSV. Человек проверяет и правит. Ценность — качество автоматических лейблов для обучения, не UX/UI.

## Кто пользователь и какую задачу закрывает

**Основной пользователь:** ML-инженер / специалист по компьютерному зрению, который готовит датасет действий человека для обучения моделей и роботов.

**Задача:** получить из короткого ролика структурированные шаги, пригодные как старт обучения, без разметки с нуля.

**Разметчик** - участник проверки, не второй продукт

Это гипотеза сегмента. Интервью с инженером ещё не проведено; кейсодатель подтвердил фокус на инженерах и оценку по модели, не по UI.

## Гипотеза сегмента и проблемы

Гипотеза: когда ML-инженер готовит датасет действий человека по коротким видео для обучения моделей, он каждый ролик размечает с нуля — сам смотрит запись, режет шаги и подписывает действие и объект — и тратит на это 15–30 минут на ролик 5–30 с, из них больше на «что произошло», чем на границы.

Откуда цифры: бриф кейсодателя, не замер у инженера. На интервью это факт, только если человек по последнему датасету подтвердит и минуты, и что узкое место — семантика. Если размечает иначе, быстрее или упирается в границы — гипотеза снята.

## Гипотеза решения

Когда ML-инженер загрузит короткий ролик с одной операцией, мы автоматически нарежем его на осмысленные шаги и подставим границы, действие и объект в JSON/CSV. Ему останется просмотреть черновик и поправить ошибки. Время до принятой разметки — 5–10 минут на ролик вместо 15–30 (в 3 раза меньше), при качестве черновика F1 ≥ 0,75 и ≥ 80% верных действий и объектов на совпавших шагах.

## Границы MVP

**В скоупе**

- загрузка MP4/MOV, 5–30 с, ≥ 720p;
- автонарезка на осмысленные шаги (не микродвижения);
- `action`, `object` (из видео, список заранее не дан), границы, keyframe;
- пересечения двух рук допустимы — как кодировать, решаем мы;
- `unknown` и паузы без действия допустимы; объекта может не быть (`null`);
- минимальный просмотр и правка одной ошибки;
- экспорт JSON/CSV по контракту шага.

**Вне скоупа**

- интеграция с Label Studio / CVAT;
- полировка UX, проекты, роли, биллинг;
- ROS, управление роботом, 3D, усилия;
- обучение большой модели с нуля;
- доверие к разметке без просмотра человеком.



## Основной сценарий

1. Пользователь загружает короткий ролик с одной операцией.
2. Пайплайн за ≤ 2 мин отдаёт шаги: границы, действие, объект, keyframe, confidence, model_version.
3. Пользователь видит черновик, правит одну реальную ошибку.
4. Выгружает финальный JSON/CSV. Для сдачи достаточно финальной разметки; черновик и историю  ревью отдельно хранить не обязательно.



## Критерии успеха (предварительные)

1. Сегментация: Step-level F1 ≥ 0,75 (one-to-one, temporal IoU ≥ 0,5 **и** верный `action`); средняя ошибка границ ≤ 2 с.
2. Семантика: на шагах с temporal IoU ≥ 0,5 доля верных `action` и `object` ≥ 80%; синонимы = совпадение.
3. Продукт: обработка ≤ 2 мин; JSON/CSV валидны на 100%.
4. Сокращение ручной работы в 3×  за счёт качества модели.

Keyframe — стилистика: середина сегмента или кадр внутри шага, без отдельной модели.

# 2. Допущения, риски и план проверки до финала

Связь продуктовых решений с пайплайном

## Пайплайн MVP (следствие продуктовых решений)

```
видео → decode (FFmpeg)
     → proposals границ (окна / change points / VLM)
     → распознать action + object (VLM, open-vocabulary)
     → keyframe = кадр внутри сегмента
     → validate schema
     → минимальный просмотр/правка
     → JSON/CSV
```


| Продуктовое решение           | Техника                                           |
| ----------------------------- | ------------------------------------------------- |
| Жюри смотрит модель, не UI    | Бюджет в сегментацию + VLM, не в фронт            |
| Шаг = осмысленный verb–object | Промпт/постпроцессинг запрещает микродвижения     |
| Объект не дан заранее         | Отдельная голова/поле `object`, возможен `null`   |
| Синонимы не режут строкой     | Нормализация + семантическое сравнение на оценке  |
| Пересечения допустимы         | Пересекающиеся интервалы в JSON, не одна дорожка  |
| Keyframe стилистика           | Середина сегмента, SAM2 не в критическом пути     |
| ≤ 2 мин                       | Мало FPS, без тяжёлого трекинга на первом прогоне |
| Сдача = финальный файл        | Не строим audit trail                             |


Готовые API допустимы; сервисы и стоимость указываем. Эталонных роликов заказчик не даст - проверяемся на Assembly101 / EPIC-KITCHENS.

## Ключевые допущения (положительная форма)

1. Скрытый тест похож на короткие однооперационные ролики в духе Assembly101/EPIC.
2. Open-vocabulary VLM на таких роликах даёт F1 ≥ 0,75 и затем ≥ 80% верных действий на совпавших шагах.
3. Ошибка границ ≤ 2 с без отдельной тяжёлой temporal-модели.
4. Инженер примет такой JSON как стартовые лейблы для обучения.



## План проверки до финала

Порядок: нарезка → семантика → скорость/экспорт → разговор. Один прогон на 8 роликах закрывает пункты 1–3.

**Проверка A — сегментация (ворота)**  
8 роликов 5–30 с, своя GT. Matching для F1: tIoU ≥ 0,5 + верный action.  
Pass: F1 ≥ 0,75 и средняя ошибка границ ≤ 2 с (только matched по IoU).  
Fail F1 < 0,50: не обещать мелкую нарезку, укрупнять шаги.

**Проверка B — семантика**  
На шагах с tIoU ≥ 0,5: accuracy action и object, синонимы = да.  
Pass: ≥ 80%.  
Fail < 60% по action: менять способ называния, не редактор.

**Проверка C — продукт пайплайна**  
1 ролик с двумя руками + замер wall-clock + валидатор JSON-контракта.  
Pass: ≤ 2 мин, 100% валидный экспорт.  
Fail по времени: резать FPS, убрать SAM2 с критического пути.

**Проверка D — ценность для инженера (без MVP)**  
30 мин: последний реальный датасет + муляж JSON + оффер «пришлите ролик — завтра черновик».  
Pass: согласен, что пошло бы в обучение как старт.  
Fail: «всё равно с нуля» — на хакатоне всё равно сдаём метрики жюри, пилот не обещаем.

## Что не проверяем до финала

Красота UI, плагин в Label Studio/CVAT, audit trail, обучение большой модели, идеальный keyframe, закрытый словарь от организаторов.

## Статус на сейчас

Приняты продуктовые границы и порядок метрик. Не принята (ещё не куплена проверкой) ставка, что скрытый тест и инженер подтвердят качество черновика. Это и есть работа до финала.
